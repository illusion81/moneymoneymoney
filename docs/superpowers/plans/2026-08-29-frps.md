# Financial Report Planner System (FRPS) Implementation Plan

> **For agentic workers:** Each task below has a self-contained mini-doc brief in
> `docs/superpowers/plans/frps/`. A subagent is dispatched per mini-doc. Steps use
> checkbox (`- [ ]`) syntax. Implement tasks using TDD (write failing test →
> watch it fail → minimal code → watch it pass → commit).

**Goal:** Add a Dart-native FRPS to the existing Flutter app — deterministic
financial tools + mock SLM + adaptive questions + report assembly + SQLite
persistence — behind a single `ReportPlanner` service.

**Architecture:** Pure-Dart logic under `lib/frps/` (no Flutter imports in
tools/models/slm/questions/reporting), tested via `flutter test`. All arithmetic
lives in `financial_tools/`; the SLM only formats already-computed numbers. The
SLM and storage sit behind interfaces for later replacement.

**Tech Stack:** Dart 3.11 (Flutter 3.41), `package:flutter_test`, `sqflite` +
`sqflite_common_ffi` (storage only). No other runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-08-29-frps-design.md`

## Global Constraints

- All financial arithmetic lives in `lib/frps/financial_tools/`; tools are pure
  (no I/O, no randomness, no `DateTime.now()`, no SLM calls).
- The SLM does zero arithmetic: `slm/` only parses text and formats numbers.
- `financial_tools/` never imports `slm/`, and `slm/` never imports
  `financial_tools/`. They meet only in `reporting/` and `report_planner.dart`.
- Tools, models, slm, questions, and reporting are pure Dart — no Flutter
  imports. Only `storage/` may import `sqflite`.
- Only the storage task may edit `pubspec.yaml`.
- Existing app files (`lib/main.dart`, `lib/models/`, `lib/services/`,
  `lib/screens/`, `test/widget_test.dart`) are untouched.
- Tests run with `flutter test test/frps/...` (single file) or `flutter test`
  (full suite). Code must pass `flutter analyze` with no new warnings.
- Each task commits ONLY its own files with `git add <paths>`.

## Dependency Graph & Waves

```text
Wave 1 (7 agents, parallel):  budget, savings, net_worth, cash_flow,
                              debt_payoff, benchmark, models
Wave 2 (1 agent):             tool_outputs  (imports the 6 tool result types)
Wave 3 (4 agents, parallel):  slm, questions, storage, reporting
                              (depend only on Wave 1 & Wave 2 artifacts)
Wave 4 (1 agent):             report_planner (depends on everything)
```

Every Wave 1 module is fully self-contained (its own types + its own test), so
the 7 agents never touch the same file and never import each other.

## Execution Notes for the Controller

- Dispatch all Wave 1 agents in parallel (single message, 7 `task` calls).
- After Wave 1 completes, dispatch Wave 2; after Wave 2, Wave 3 (parallel);
  after Wave 3, Wave 4.
- After each wave, run `flutter analyze` and the relevant `flutter test` files.
- Final gate: `flutter analyze` clean + `flutter test` fully green.
- The `lib/frps/` imports use the package name `moneymoneymoney`
  (e.g. `package:moneymoneymoney/frps/financial_tools/budget_calculator.dart`),
  matching the existing `package:moneymoneymoney/models/...` imports.
